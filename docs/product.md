# Product Specification

## Application

MasterCangjie - Cangjie Programming Language Interactive Coding Platform & Training Assessment

**Tags:** `website`, `roadmap`, `interactive`, `coding`, `practice`, `training`, `CodeChum`, `LeetCode`, `coding-platform`, `built-in-coding-topics`, `Cangjie`, `online-coding-website`, `assessment`, `test-cases`, `Cangjie-roadmap`

## Actors

| Actor              | Goal and responsibilities                                                                                                                                                                                                    |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Visitor            | Register or sign in using Google.                                                                                                                                                                                            |
| Learner            | Learn Cangjie, practice coding or answer multiple-choice questions, receive feedback, complete topics, unlock progression, and review performance. Students and existing programmers are audience segments within this role. |
| Content maintainer | Prepare and correct topics, lessons, coding problems, test cases, multiple-choice activities, prerequisites, and scoring criteria.                                                                                           |

## Core workflows

| Workflow                      | Expected sequence and outcome                                                                                                                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account access                | Register or sign in with Google → reach the dashboard. Learners can sign out. Direct learners who lose access to their Google account to Google's account recovery process.                                          |
| Start learning                | View the roadmap → understand available and locked topics → select an unlocked topic → open its learning material and activity.                                                                                    |
| Instructions before practice  | Each topic includes brief lessons or summaries. Mandatory onboarding must be completed first. After onboarding, reading the learning material is encouraged but does not gate access to an unlocked topic's activity. |
| Coding practice and debugging | Read problem instructions and visible test details → edit Cangjie code → run an individual test → inspect feedback → revise. Hidden tests expose pass/fail only.                                                  |
| Validate a coding problem     | Run all tests for the current code → receive a problem score → retry after the validation cooldown.                                                                                                                 |
| Multiple-choice practice      | Open a topic without coding problems → answer its ten multiple-choice questions → review selections → submit → receive a score and feedback. Learners may retry.                                                  |
| Submit a topic                | Review the topic attempt → confirm submission → evaluate eligible work → receive a final topic score. Identify incomplete work before confirmation.                                                                |
| Complete and unlock           | Pass a coding topic to complete it. For a topic without coding problems, pass its multiple-choice activity and select "Mark complete." Completion unlocks the next topic in the defined roadmap order.                |
| Resume learning               | Return or sign in again → restore the previous topic and activity, code drafts or answer selections, recorded scores, and progress. Clearly identify work that has not yet synced.                                   |
| Review performance            | View completed topics, solved coding problems, multiple-choice results, scores, and the next available learning step.                                                                                                 |
| Manage profile                | Add or update a profile photo and bio, edit the username or contact email, and bind or change a mobile number. Verify a new contact email or mobile number before it becomes active.                                  |

## Business Rules

| Area                                      | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account access                            | Google is the only registration and sign-in method in the MVP. Password-based, Facebook, GitHub, and other sign-in methods and account linking are deferred. Signing out does not delete saved learner work or progress.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Supported language                        | The editor supports Cangjie only. The MVP supports Cangjie LTS 1.0.5. Exercises in the online editor must compile and run as terminal or console programs. Starting servers or launching UI applications is unsupported.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Activity types                            | Coding topics contain coding problems. Topics without coding problems contain lessons or summaries and exactly one multiple-choice activity. "Lesson-only topic" means a topic without coding exercises; it still has a scored multiple-choice assessment. This rule includes the first two onboarding topics, Identifiers, Unit, and Nothing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Topic access                              | The roadmap is sequential. The first onboarding topic is initially unlocked; each subsequent topic requires completion of the previous topic in the explicit MVP roadmap order. Topic categories group topics and do not receive separate scores. All three onboarding topics must be completed before Basic Concepts becomes available. Problems within an unlocked coding topic can be accessed in any order.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Onboarding completion                     | Getting Started with Cangjie and Installing the Cangjie Toolchain each require a submitted multiple-choice score of at least 60/100 and the learner selecting "Mark complete." Running the First Cangjie Program requires submitting the Hello World exercise and passing its single test case. The onboarding content follows the [Getting Started with Cangjie documentation](https://cangjie-lang.cn/en/docs?url=%2F1.0.0%2Fuser_manual%2Fsource_en%2Ffirst_understanding%2Fbasic.html).                                                                                                                                                                                                                                                                                                                                         |
| Optional reading and completion           | After onboarding, reading lessons is optional. A topic without coding exercises must still have its multiple-choice activity passed and then be marked complete before the next topic unlocks. "Mark complete" is enabled after a passing submitted score; clicking it does not replace the assessment or require proof that the learner read every lesson.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Topic selection                           | Learners may choose any unlocked topic from the dashboard, including previously completed topics for practice or retries.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Coding problem score                      | Each passed test case earns 10 points. All test cases, including hidden tests, count equally. A problem's maximum score is its test count multiplied by 10. For example, passing four of seven tests earns 40/70 points; passing all seven earns the perfect score of 70/70.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Coding failures                           | A compilation failure earns zero for that validation. A runtime error or timeout fails the affected test; other tests continue where possible. Compilation errors are reported for the code as a whole; execution failures identify the affected test. Hidden tests reveal pass/fail only and withhold diagnostic output and differences. Evaluation service failures are unevaluated attempts, not learner failures.                                                                                                                                                                                                                                                                                                                                                                                                              |
| Individual versus batch runs              | An individual run evaluates one test and gives pass/fail feedback without awarding points. A batch validation evaluates all tests for one code version and awards the sum of passed test points. A result applies only to the code version that was evaluated.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Multiple-choice scoring                   | Every multiple-choice activity throughout the product contains exactly ten questions, each worth 10 points, for a maximum of 100 points. Each question has one correct answer; a correct selection earns 10 points and an incorrect or unanswered question earns zero. There is no partial credit within a question. Selections remain editable before submission. Submission scores the current selections and shows the results.                                                                                                                                                                                                                                                                                                                                                                                                 |
| Passing a topic                           | A submitted score must be at least 60% of the topic's total possible points. For a coding topic, sum the earned points across all its problems and divide by the maximum possible points across all those problems. Problems with more tests intentionally contribute more to the topic score; the content maintainer chooses test counts accordingly. A multiple-choice topic passes with at least 60/100 points, or six correct answers. Passing completes a coding topic; a multiple-choice topic additionally requires "Mark complete."                                                                                                                                                                                                                                                                                        |
| Attempted and unattempted coding problems | A problem is attempted when the learner has edited its starter code or requested a code run or validation for it. An untouched problem with no run or validation is unattempted. Merely opening a problem does not make it attempted. Unattempted problems contribute zero points to a submitted topic score; they remain part of the topic's maximum possible points.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Final submission                          | Show a review and confirmation before finalizing a topic submission. For coding topics, validate the latest code for every attempted problem that lacks a batch result for that code version, including code changed after validation. Reuse results only when they apply to the current code. Do not require validation of unattempted problems; these contribute zero after the learner confirms the incomplete submission. Calculate the submitted topic score from the current eligible problem results. For a multiple-choice topic, submit and score the current ten answer selections; allow unanswered questions to contribute zero after confirmation. If evaluation fails because of a service error, leave the submission unfinalized and allow retry without replacing existing scores, completion status, or unlocks. |
| Learner statistics                        | A coding problem counts as solved when the learner passes all its tests in a batch validation. Individual runs do not count. Retain this achievement after later lower-scoring retries. Report multiple-choice activity results separately from solved coding problems. A completed-topic count includes coding topics passed through submission and multiple-choice topics both passed and marked complete.                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Validation cooldown                       | After requesting batch validation, the learner must wait at least five seconds before requesting another batch validation. Show the remaining cooldown with a progress indicator and a disabled Validate button. Keep the button disabled while validation is still running, even if five seconds have elapsed. Prevent repeated clicks from creating overlapping requests for the same action.                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Progress after retry                      | Retain the learner's highest finalized submission score for each topic, including a multiple-choice score awaiting "Mark complete." A later lower-scoring submission does not replace that score, undo completion, or relock previously unlocked topics. This applies to coding and multiple-choice topics. Show the current attempt's result separately from the retained best score when they differ. A multiple-choice retry does not require a previously completed topic to be marked complete again.                                                                                                                                                                                                                                                                                                                         |
| Visible and hidden tests                  | Visible tests expose their details and expected output. Selected coding problems may include hidden tests. Show a hidden test's existence and pass/fail status, but replace its details with "This test case is hidden." Do not expose its inputs, expected output, console output, or output differences. Learners may run hidden tests individually for pass/fail feedback, and batch validation includes them in the score.                                                                                                                                                                                                                                                                                                                                                                                                     |
| Profile changes                           | Profile customization is available at launch and optional for learners. Learners can change their username, profile photo, bio, contact email, and bound mobile number. Retain the current verified contact until replacement verification succeeds. The editable contact email is separate from the Google sign-in identity; changing a contact email or mobile number does not change the Google account used to access MasterCangjie.                                                                                                                                                                                                                                                                                                                                                                                           |

## Product Entities

These are product concepts and relationships, not a technical data model.

| Entity                    | Meaning and important relationships                                                                                                |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Learner account           | Google sign-in identity, username, profile, verified contact details, and account status.                                          |
| Sign-in method            | Google account access for the MVP. Other providers and linking methods to one account are deferred.                                |
| Roadmap                   | An ordered learning path containing topic categories, onboarding, topics, and prerequisites.                                       |
| Topic                     | A learning unit containing lessons and either coding problems or a multiple-choice activity, with scoring and completion criteria. |
| Topic category            | A grouping of related topics, such as Basic Concepts or Basic Data Types. Categories do not have their own assessments.            |
| Prerequisite relationship | Determines which completed topic permits access to the next topic.                                                                 |
| Coding problem            | Instructions, constraints, starter code, expected behavior, and associated tests.                                                  |
| Test case                 | Input or setup, expected output, visibility, and a possible contribution of 10 points.                                             |
| Multiple-choice activity  | A topic's fixed assessment of ten questions, worth 100 points in total.                                                            |
| Multiple-choice question  | A prompt, answer choices, and one correct answer, worth 10 points.                                                                 |
| Activity draft            | A learner's current code for a problem or answer selections for a multiple-choice activity.                                        |
| Run / validation attempt  | Evaluation of a particular code version against one or more tests.                                                                 |
| Test result               | Outcome and permitted feedback for one test within an attempt.                                                                     |
| Multiple-choice attempt   | A submitted set of answer selections and its per-question results and score.                                                       |
| Topic submission          | The evaluated work for one topic attempt, its final score, and its pass/fail outcome.                                              |
| Learner progress          | Unlocked and completed topics, retained best scores, solved coding problems, and resume location.                                  |
| Contact verification      | A pending contact-email or mobile-number change and its verification outcome.                                                      |

## Edge cases and required behavior

| Edge case                                                                       | Expected product behavior                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Code changes after successful validation                                        | Mark the code as "Changed since last validation." Do not present earlier results as current. Final submission must validate the current code before crediting that problem.                                                                                                                                                                                                                                                                               |
| Learner submits an incomplete topic                                             | Show unattempted coding problems or unanswered multiple-choice questions and request confirmation. Allow submission with these items contributing zero. An attempted coding problem awaiting evaluation must be evaluated before the submission can be finalized.                                                                                                                                                                                         |
| Learner passes a multiple-choice activity but has not marked the topic complete | Retain the passing score and show "Mark complete" as the next action. Keep the next topic locked until the learner marks this topic complete.                                                                                                                                                                                                                                                                                                             |
| Compilation error, crash, timeout, or excessive output                          | Distinguish the outcome from an incorrect answer. Show permitted details for visible tests; keep hidden-test output and diagnostics concealed. Compilation or execution failures in learner code may yield zero points; a platform evaluation failure does not.                                                                                                                                                                                           |
| Evaluation service fails during validation or submission                        | Identify the attempt as unevaluated. Do not finalize a submission using zero points as a substitute for the missing evaluation. Preserve prior recorded scores and progress, and offer a retry.                                                                                                                                                                                                                                                           |
| Output differs only in spacing or line endings                                  | Require exact output matching. Differences in line endings, leading or trailing whitespace, tabs, spaces, or newlines fail the test. For visible tests, green markers indicate matching output, orange markers identify formatting differences, and red markers identify other differences. Any difference means the test fails. Include text or symbols alongside colors so feedback does not depend on color alone. Hidden tests expose only pass/fail. |
| Learner leaves, signs out, or loses connectivity while working                  | Preserve progress, scores, unlocks, resume location, code drafts, and multiple-choice answer selections. Restore saved work on return or sign-in. Keep offline edits until they sync and identify unsynced work. Do not award points or finalize a submission without a confirmed evaluation result. Submitted answers and results remain recorded; later edits belong to a new attempt.                                                                  |
| Different tabs or devices contain conflicting drafts                            | Notify the learner rather than silently overwriting work. Preserve both conflicting code drafts or answer selections until the learner chooses which to keep. Clearly identify the chosen current draft and require validation or submission appropriate to that draft. Existing best scores and unlocks remain intact.                                                                                                                                   |
| Repeated clicks during validation, submission, or completion                    | Show one pending action and one consistent outcome. Prevent duplicate requests from producing duplicate submissions or inconsistent progress.                                                                                                                                                                                                                                                                                                             |
| Learner accesses a locked topic directly                                        | Enforce the prerequisite and explain which topic must be completed first.                                                                                                                                                                                                                                                                                                                                                                                 |
| A lower-scoring retry follows a passing submission                              | Show the retry's result while retaining the best finalized topic score and all earned completion and unlocks. A previously earned passing multiple-choice score remains eligible for "Mark complete."                                                                                                                                                                                                                                                     |
| A problem, test, or multiple-choice question is corrected after completion      | Wording-only fixes do not affect scores. If a correction could affect scoring, use the corrected version for future evaluations and notify affected learners. Do not require retries, reduce recorded best scores, undo completion, or revoke unlocks. Learners may retry voluntarily.                                                                                                                                                                    |
| A future social sign-in method conflicts with an existing account               | Account linking is deferred beyond the Google-only MVP. Any later provider must have an explicit linking or recovery policy before release. Do not merge accounts solely because email addresses match.                                                                                                                                                                                                                                                   |
| Verification expires or a contact is already in use                             | Retain the current verified contact and preserve account access. Explain the reason and allow the learner to retry verification or choose another contact.                                                                                                                                                                                                                                                                                                |
| Learner loses access to their Google account                                    | Direct the learner to Google's account recovery process. A verified MasterCangjie contact email or mobile number does not create an alternative sign-in method in the MVP.                                                                                                                                                                                                                                                                                |
| A new learner has no statistics                                                 | Explain that there is no practice history yet and direct the learner to the first onboarding topic.                                                                                                                                                                                                                                                                                                                                                       |

Assessment scores reflect performance on the provided coding tests or multiple-choice questions. They do not, by themselves, establish broad language mastery or suitability for high-stakes assessment.

## MVP scope

- **Account access:** Google registration and sign-in, sign-out, and guidance to Google's account recovery process. Facebook, GitHub, password-based sign-in, and account linking are deferred.
- **A bounded beginner roadmap:** The following ordered path contains reviewed lessons and assessments. Categories group topics; progression follows the listed topic order within and across categories.

  1. **Getting Started with Cangjie — mandatory onboarding**
     - Getting Started with Cangjie: lessons, summaries, and a ten-question multiple-choice activity.
     - Installing the Cangjie Toolchain: lessons, summaries, and a ten-question multiple-choice activity.
     - Running the First Cangjie Program: lessons, summaries, and a Hello World coding exercise with one test case.
  2. **Basic Concepts**
     - Identifiers: lessons, summaries, and a ten-question multiple-choice activity.
     - Program Structure: lessons, summaries, and coding problems.
     - Expressions: lessons, summaries, and coding problems.
     - Functions: lessons, summaries, and coding problems.
  3. **Basic Data Types**
     - Basic Operators: lessons, summaries, and coding problems.
     - Integer: lessons, summaries, and coding problems.
     - Floating Point: lessons, summaries, and coding problems.
     - Boolean: lessons, summaries, and coding problems.
     - Character: lessons, summaries, and coding problems.
     - String: lessons, summaries, and coding problems.
     - Tuple: lessons, summaries, and coding problems.
     - Array: lessons, summaries, and coding problems.
     - Range: lessons, summaries, and coding problems.
     - Unit: lessons, summaries, and a ten-question multiple-choice activity; no coding exercises.
     - Nothing: lessons, summaries, and a ten-question multiple-choice activity; no coding exercises.
- **Learning material:** Brief lessons or summaries based on the official [Cangjie User Manual](https://cangjie-lang.cn/en/docs?url=%2F1.0.0%2Fuser_manual%2Fsource_en%2Ffirst_understanding%2Fbasic.html) and [API Reference](https://cangjie-lang.cn/en/docs?url=%2F1.0.0%2Flibs%2Fstd%2Fstd_module_overview.html). Reading after onboarding is optional.
- **Cangjie practice:** Problem navigation, code editing, individual-test execution, and full-test validation.
- **Multiple-choice practice:** Exactly ten questions per activity, answer selection and recovery, submission, scored feedback, retries, and a required completion action after passing.
- **Actionable feedback:** Test status, actual and expected output and differences for visible tests, pass/fail only for hidden tests, and multiple-choice results after submission.
- **Scoring and completion:** Ten points per test or correct multiple-choice answer, a 60% topic passing threshold, current-work evaluation, incomplete-submission confirmation, best-score retention, and predictable unlocks.
- **Continuity:** Saved topic progress, scores, unlocks, resume location, code drafts, and multiple-choice answer selections, with clear offline and conflict recovery behavior.
- **Basic learner statistics:** Completed topics, solved coding problems, multiple-choice results, retained best scores, and the next available learning step.
- **Profile customization:** Learners may edit their username, profile photo, bio, contact email, and bound mobile number. Customizing these fields is optional; new contact emails and mobile numbers require verification. Contact changes do not alter the Google sign-in identity.

**The MVP is complete when a learner can register and sign in with Google, complete the mandatory onboarding and the chosen beginner path through coding and multiple-choice activities, understand scores and unlocks, resume saved work, customize their profile and verify contact changes, and sign out successfully.**

## Explicit non-goals

- Product-facing topic creation or deletion workflows. The content maintainer still prepares and corrects the launch curriculum, tests, and multiple-choice questions.
- User search.
- Editors for programming languages other than Cangjie.
- Facebook, GitHub, password-based sign-in, alternative contact-based sign-in, and account linking in the MVP.
- Classes, instructor assignments, gradebooks, and institutional reporting.
- Proctoring, plagiarism detection, identity-assured exams, and certificates.
- Public profiles, leaderboards, social feeds, and multiplayer competition.
- General-purpose development environments, arbitrary projects, and third-party package installation.
- Complete coverage of the Cangjie manual and standard-library API. The MVP covers the selected learning path and may expand later.
- Payments and subscriptions.
